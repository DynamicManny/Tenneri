API Fundamentals

How software talks to software, taught through one small business

Meet Solebound, an independent shoe store with two locations and a busy online shop. Its founder, Amara, has no IT department. Her business runs on a handful of APIs that pass orders, payments and text messages between the tools she already pays for. This module shows what's happening under the hood, then hands you a key to Solebound's API so you can make the calls yourself.

Learning objectives

By the end of this module, you will be able to:

  1. Explain what an API is and identify the APIs a small business depends on.
  2. Break an HTTP request and response into their parts, and read a status code.
  3. Send requests to a working API, then diagnose and fix the errors you cause.
  4. Tell authentication from permission, and apply the basic rules of key safety.
  5. Read API documentation well enough to use an endpoint you've never seen.

Section 1 · The concept

APIs are all around you

An API is an agreed way for two pieces of software to talk to each other. You don't need to know how the other system works inside. You only need to know what to ask for and how to ask for it.

Amara doesn't have a developer on staff. She connected her tools with a few small cloud functions: short scripts that run on Google Cloud whenever something happens. When a customer checks out on Solebound's Shopify store, nobody emails Amara the order. Shopify sends an HTTP request to a web address her function is listening on, with the order packed inside as JSON. The function reads it and updates the stock count. That exchange is an API call.

APIs are how the modern internet works. Every app you've used today has made dozens of them. They aren't only for developers. They're the language connected systems use to talk, and understanding them is the first step to building those connections.

Section 4 · Security

Authentication and API keys

An API lives at a public web address. Without authentication, anyone who found the address could call it. Auth is how an API knows you're allowed to be there, and what you're allowed to do.

The API key rules every practitioner lives by
⚠️
The most common mistake: typing an API key straight into code that ends up in a public GitHub repository. It happens constantly, and automated scanners often find exposed keys within minutes. Keep keys in environment variables or a secrets manager. Always.
